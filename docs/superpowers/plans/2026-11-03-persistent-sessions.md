# Persistent sessions and mixer presets

User requests all settings survive closing/upgrading; presets must include mixer settings. Existing input EQ deliberately saves/loads Enabled=false and presets version1 contain only driver settings. Change this policy to restore saved Enabled values. Use stable LocalAppData/DonnerControlPanel storage, atomic writes with previous-file backups, no installer defaults copied over user files. No audio/user config is published to GitHub.

MixerConfiguration captures the app-supported Banana float parameters (gain/mute/mono/routes/comp/gate/virtual tone/bus EQ), six device bindings (type, stable ID and name), microphone EQ, native preferred sample rate and editor selections/link/channel settings. Capture native baseline on first connected launch without changing parameters. Subsequent launches restore saved state using only differences. Missing devices are retained in desired configuration instead of selecting a different device; retry on reconnect/manual refresh. Save successful user actions and flush queued changes on close. Never overwrite valid saved configuration with disconnected/default snapshots or partial restore results.

Extend preset schema to v2 with optional mixer configuration; accept existing v1 without mixer and leave mixer unchanged when applying them. Include disabled mixer and last saved mixer settings. Validate complete profiles before writes; preserve partial/pending restores if a device is unavailable. Preset preview shows mixer presence, bindings and EQ enable states. Keep existing driver validation and add app-session preferences/hardware snapshot restore, meter/link/UI editor selections. OS device format and custom naming already persist in Windows and existing backups.
